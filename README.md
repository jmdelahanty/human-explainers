# human-explainers

Visual explainers for how the acquisition-to-analysis pipeline works, generated
from the contracts and code that actually run it.

The first explainer answers: *how is the geometry of a recording computed
across Orange, Citrus, and Palette?*

## The one rule

**Nothing here is written by hand.** Every content block on a page is a
verbatim excerpt of a file in a source repository at a pinned commit, with a
link back to that exact line range. Diagrams are parsed from the text of an
excerpt on the same page. The only words a curator writes are page titles,
section headings, and short notes that are visibly set apart from the quoted
content.

This keeps the site honest: if the explainer and the code disagree, the
explainer is stale, never wrong on its own, and `verify` will say so.

## Layout

| Path | What it is |
|---|---|
| `sources.yaml` | The source repos (agent-contracts, orange, citrus, palette) and where they are checked out locally. |
| `sources.lock.json` | The commit each source is pinned to. Generated by `lock`. |
| `explainers/*.yaml` | One curated selection per explainer: which sections, symbols, or line ranges to quote, in what order, and which diagrams to derive from them. |
| `tools/explain.py` | The generator. Reads sources with `git show <commit>:<path>` so uncommitted edits never leak in. |
| `site/` | Generated static HTML. Served by GitHub Pages. |
| `context/` | Generated markdown bundles of the same excerpts, for agents to read. |
| `site/manifest.json` | Hash and provenance of every excerpt, used by `verify`. |

## Usage

```bash
pip install -r requirements.txt
python3 tools/explain.py lock     # pin sources to current local HEADs
python3 tools/explain.py build    # write site/ and context/
python3 tools/explain.py verify   # re-extract and compare against manifest
```

Open `site/index.html` in a browser.

## Selecting content

An explainer YAML lists sections of items. Each item is one of:

```yaml
- id: frames-contract            # unique within the explainer
  source: agent-contracts        # key from sources.yaml
  path: orange-citrus/physical_layout_calibration_contract.md
  heading: "## Canonical Coordinate Frames"   # exact ATX heading; section runs to the next heading of equal or higher level

- id: palette-apply-homography
  source: palette
  path: src/fisheye/shared/coordinate_transform.py
  symbol: apply_homography_xy    # Python function/class located with ast

- id: citrus-arena-origin-writer
  source: citrus
  path: src/logging/session_logger.cpp
  lines: [5677, 5706]            # 1-indexed inclusive
  anchor: arena_origin_in_canvas_x_px   # build fails if this text is not inside the range

- diagram:
    kind: transform-chain        # parses `p_<frame> = ...` equations from the named excerpt
    from: citrus-transform-chain
    order: [p_camera_view, p_final_display_canvas, p_arena_relative_canvas]
```

Diagram kinds: `transform-chain` (equations in code fences become nodes and
arrows) and `bullet-cards` (top-level `` `term` `` bullets with nested bullets
become definition cards). `order` only arranges nodes; it cannot add any.

## Re-pinning

When a source repo moves on, run `lock`, then `build`. If a heading was renamed
or a line range drifted past its anchor, `build` fails and names the excerpt,
so the selection can be fixed deliberately rather than silently quoting the
wrong thing.
