citrusdocs/coordinate_systems.mdL198–L210heading: ### `projector_body_frame`view at 48ad93e4d2

projector_body_frame

The physical coordinate frame attached to the projector chassis.

  • Status: Manual rig metadata
  • Units: degrees about the optical axis
  • Current field:
    • projector_mount_rotation_deg_about_optical_axis
  • Evidence:
    • configured in src/core/rig_config.h
    • stored in /rig_snapshot

This frame is not automatically inferred from homography or xrandr.

citrusdocs/coordinate_systems.mdL183–L196heading: ### `display_output_transform`view at 48ad93e4d2

display_output_transform

The runtime desktop/session transform for the configured stimulus display output.

  • Status: Code-defined runtime snapshot
  • Source: xrandr --query
  • Examples:
    • output name such as DP-3
    • transform token such as normal or inverted
  • Evidence:
    • parsed from xrandr in src/core/display_snapshot.cpp
    • stored under /display_snapshot

This is not the same thing as physical projector-body orientation.

citrusdocs/coordinate_systems.mdL155–L181heading: ### `camera_view_to_canvas_mapping`view at 48ad93e4d2

camera_view_to_canvas_mapping

The effective mapping from camera_view_px into the stimulus canvas, computed from the active homography.

  • Status: Calibration-derived
  • Nature:
    • point mapping via homography
    • local direction mapping via finite differences around the active arena center
  • Evidence:
    • camera points are transformed into stimulus coordinates with cv::perspectiveTransform in src/ipc/ShamanIPCReader.cpp
    • direction basis is derived in src/calibration/direction_frame_mapping.h
    • saved H5 fields live under /calibration_snapshot/<camera_id> and /calibration_snapshot/arena_geometry

The OpenCV sidecar homography_<arena>_<camera>.yml and the H5 /calibration_snapshot/<camera_id>/homography_matrix represent the same direction:

camera_view_px -> final_display_canvas_px

The homography source points are camera-image pixels from the calibration image. For current Orange/Citrus workflows these should be full raw camera-frame pixels when the source image is the native camera frame. If a future calibration is derived from a crop or downsampled image, that source image shape and crop transform must be documented in the artifact before Orange can consume it safely.
